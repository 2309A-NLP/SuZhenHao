# 招股说明书智能问答系统 — 技术文档

## 1. 项目概述

### 1.1 项目简介

本项目是一个基于 **RAG（Retrieval-Augmented Generation，检索增强生成）** 技术的智能问答系统，专门针对招股说明书等金融文档进行深度解析。系统能够自动读取 PDF 文档，将其拆分为语义片段并建立向量索引，当用户提出问题时，系统先从文档中检索最相关的内容，再结合大语言模型（LLM）生成准确、有据可依的回答。

### 1.2 技术栈

| 层级 | 技术 | 用途 |
|------|------|------|
| LLM 服务 | DeepSeek API (`deepseek-chat`) | 自然语言理解与回答生成 |
| 向量嵌入 | Sentence Transformers (`paraphrase-multilingual-MiniLM-L12-v2`) | 文本向量化 |
| 向量数据库 | FAISS (Facebook AI Similarity Search) | 高效向量相似度检索 |
| PDF 解析 | PyPDF2 / pdfplumber | PDF 文本提取 |
| Web 后端 | FastAPI + Uvicorn | RESTful API 服务 |
| Web 前端 | 原生 HTML/CSS/JavaScript | 用户交互界面 |
| 备选 UI | Streamlit | 快速原型 Web 界面 |
| 运行环境 | Python (`D:/an10-1/envs/nlp_2/python.exe`) | 主要开发语言 |

### 3.2 document_loader.py — 文档加载与文本分块

**职责**：读取 PDF 文件并将其拆分为适合向量化的文本块。

#### 3.2.1 DocumentLoader 类

- **PDF 加载策略**：优先使用 `pdfplumber`（提取质量更高），失败后自动回退到 `PyPDF2`。
- **加密 PDF 处理**：检测加密 PDF 并尝试空密码解密；若缺少 `PyCryptodome` 则抛出明确错误。
- **输出格式**：返回文档列表，每项包含 `text`（页面文本）和 `metadata`（页码信息）。

#### 3.2.2 TextChunker 类

- **分块算法**：基于固定窗口大小的滑动窗口分块，支持以下特性：
  - 在空格处断句（避免截断词语）
  - 相邻块之间有重叠区域（默认 100 字符），确保上下文连贯
  - 过滤掉长度不足 10 字符的无效片段
  - 每处理 50 个文档触发一次垃圾回收（`gc.collect()`），控制内存使用

- **分块参数**：
  - `chunk_size = 800`：每个文本块约 800 字符
  - `overlap = 100`：相邻块重叠 100 字符

#### 3.2.3 prepare_documents() 函数

顶层便捷函数，串联加载和分块两个步骤，返回最终的文本块列表。

---

### 3.3 embedding.py — 向量化与检索

**职责**：将文本块转换为向量，并提供高效的相似度检索能力。

#### 3.3.1 EmbeddingManager 类

- **模型加载**：尝试加载本地缓存的 Sentence Transformers 模型（`local_files_only=True`），失败则进入兜底模式。
- **兜底编码**（`_fallback_encode`）：当 Sentence Transformers 不可用时，使用基于哈希的简易向量化（256 维），保证系统仍可运行（精度较低）。
- **批量编码**：以 256 个文本为一批进行向量化，每 10 批触发一次垃圾回收。

#### 3.3.2 FAISSRetriever 类

- **索引构建**：使用 `IndexFlatIP`（内积索引）构建 FAISS 索引，向量在入库前进行 L2 归一化。
- **索引持久化**：构建完成后自动保存 `faiss.index` 和 `chunks.pkl` 到磁盘。
- **检索逻辑**：
  1. 将查询向量 L2 归一化
  2. 执行 `index.search()` 获取 Top-K 结果
  3. 过滤低于 `SIMILARITY_THRESHOLD`（0.3）的结果
  4. 返回包含 `chunk_id`、`content`、`page`、`similarity`、`distance` 的结果列表

#### 3.3.3 LocalRetriever 类

- **用途**：当 `faiss-cpu` 未安装时的轻量级备选检索器。
- **检索方式**：逐个计算查询向量与所有文本块向量的余弦相似度，排序后返回 Top-K。
- **持久化**：保存 `chunks.pkl` 和 `embeddings.npy`。

#### 3.3.4 RAGRetriever 类

- **统一入口**：封装 `EmbeddingManager` 和底层检索器（`FAISSRetriever` 或 `LocalRetriever`）。
- **自动选择后端**：根据 `faiss` 是否可用自动选择检索后端。
- **核心方法**：
  - `initialize(chunks)`：首次构建索引
  - `retrieve(query, k)`：查询检索
  - `load_from_index()`：从磁盘加载已有索引

### 3.4 query_processor.py — 查询理解

**职责**：对用户输入的问题进行意图识别、分解和关键实体提取。

#### 3.4.1 意图分类

系统预定义了 6 类查询意图：

| 意图类别 | 触发关键词 |
|----------|-----------|
| 财务信息 | 财务、收入、利润、成本、资产、负债、现金 |
| 公司信息 | 公司、企业、组织结构、管理团队、高管、股东 |
| 产品服务 | 产品、服务、业务、主营业务、经营范围 |
| 风险分析 | 风险、不确定性、竞争风险、市场风险 |
| 发展战略 | 战略、规划、目标、发展方向 |
| 市场分析 | 市场、行业、竞争、市场规模、增长率 |

未匹配任何类别时返回 `"一般信息"`。

#### 3.4.2 查询分解

支持按连接词（"并且"、"和"、"还有"、"另外"、"以及"、"、"）将复合问题拆分为多个子问题。

#### 3.4.3 实体提取

- **时间表达**：匹配 `YYYY年`、`第X季度` 等模式
- **数字/金额**：匹配数字及单位（万、亿等）
- **关键词**：去除停用词后提取有效词汇

### 3.5 llm_agent.py — LLM 代理与回答生成

**职责**：调用 LLM API 生成回答，并提供本地兜底机制。

#### 3.5.1 DeepSeekLLM 类

- **API 调用**：通过 HTTP POST 请求调用 DeepSeek Chat Completions API。
- **请求参数**：`model`、`messages`、`max_tokens`、`temperature`、`stream=False`。
- **连接测试**：`test_connection()` 方法发送简单请求验证 API 可用性。
- **错误处理**：捕获网络异常和 API 错误，返回可读的错误信息。

#### 3.5.2 RAGGenerator 类

- **Prompt 构建**：
  ```
  系统提示：你是一个专业的问答助手。请严格依据提供的参考文档回答...
  
  参考文档：
  [参考1] 第X页，相关度 XX%
  {文档内容}
  
  用户问题：
  {问题}
  
  请给出简洁、准确的答案。
  ```

- **兜底回答**：当 LLM 不可用时，直接截取检索结果的前 160 字符作为参考线索返回。
- **置信度计算**：
  ```
  confidence = max_similarity × 0.7 + min(doc_count / 5, 1.0) × 0.3
  ```
  取最大相似度和文档数量的加权值，上限为 1.0。

#### 3.5.3 QASystem 类

- **职责**：串联查询处理、文档检索和答案生成的完整流程。
- **answer(query) 方法流程**：
  1. 调用 `QueryProcessor.process_query()` 进行查询分析
  2. 调用 `RAGRetriever.retrieve()` 检索相关文档
  3. 调用 `RAGGenerator.generate_answer()` 生成最终回答
  4. 返回包含 `query`、`answer`、`sources`、`confidence` 的结果字典

## 4. 数据流

### 4.1 索引构建流程（首次运行）

```
PDF 文件
  │
  ▼
DocumentLoader.load_pdf()     ──→  页面文本列表 [text1, text2, ...]
  │
  ▼
TextChunker.chunk_documents()  ──→  文本块列表 [{content, page, chunk_id}, ...]
  │
  ▼
EmbeddingManager.embed_texts() ──→  向量矩阵 (N × dim)
  │
  ▼
FAISSRetriever.build_index()   ──→  FAISS 索引 + chunks.pkl（持久化到磁盘）
```

### 4.2 查询处理流程

```
用户问题 "公司2023年收入是多少？"
  │
  ▼
QueryProcessor.process_query()
  │  ├─ 意图识别 → "财务信息"
  │  ├─ 查询分解 → ["公司2023年收入是多少？"]
  │  └─ 实体提取 → {time: ["2023年"], keywords: [...]}
  │
  ▼
RAGRetriever.retrieve()
  │  ├─ EmbeddingManager.get_embedding() → 查询向量
  │  └─ FAISSRetriever.retrieve() → Top-K 相关文档块
  │
  ▼
RAGGenerator.generate_answer()
  │  ├─ 构建 Prompt（系统提示 + 参考文档 + 用户问题）
  │  ├─ 调用 DeepSeek API 生成回答（或本地兜底）
  │  └─ 计算置信度
  │
  ▼
返回结果 {query, answer, confidence, sources}
```

## 5. 降级与容错机制

系统在多个层面实现了降级策略，确保在依赖缺失时仍可运行：

| 场景 | 降级方案 |
|------|---------|
| `pdfplumber` 不可用 | 自动回退到 `PyPDF2` |
| `sentence-transformers` 不可用 | 使用基于哈希的简易向量化（256 维） |
| `faiss-cpu` 不可用 | 使用 `LocalRetriever` 进行余弦相似度检索 |
| DeepSeek API 不可用 | 使用 `RAGGenerator._fallback_answer()` 返回文档片段摘要 |
| DeepSeek API 调用失败 | 自动切换到本地兜底回答 |
| 索引文件不存在 | 从 PDF 重新构建索引 |
| 加密 PDF | 尝试空密码解密，缺少依赖时抛出明确错误 |

## 8. 性能考量

| 方面 | 设计策略 |
|------|---------|
| 内存管理 | 每 50 个文档处理后触发 `gc.collect()`；批量嵌入每 10 批回收一次 |
| 索引复用 | 索引构建后持久化到磁盘，避免重复构建 |
| 懒加载 | `app_core.py` 中 QA 系统采用懒加载单例模式 |
| 批量处理 | 嵌入计算以 256 条为一批，平衡速度与内存 |
| 检索效率 | FAISS `IndexFlatIP` 提供 O(n) 的精确检索；大规模场景可升级为近似检索索引 |

## 9. 扩展建议

1. **支持更多文档格式**：扩展 `DocumentLoader` 以支持 Word、TXT、HTML 等格式
2. **多文档知识库**：支持同时索引多个 PDF 文件
3. **对话历史**：在 QA 系统中引入对话上下文，支持多轮对话
4. **检索优化**：引入重排序（Reranker）模型对检索结果二次排序
5. **用户认证**：为 Web API 添加用户登录和权限管理
6. **数据库存储**：将问答历史持久化到数据库
7. **异步处理**：将 LLM 调用改为异步，提升并发能力
