# 📊 招股说明书智能问答系统（多PDF+图片理解版） - 优化点分析报告

> 工单4 在工单3 多PDF基础上新增了图片理解功能（Qwen-VL）。本报告聚焦新增模块的优化点。

---

## 一、图片处理模块优化 🖼️

### 1.1 图片分析无缓存
**现状：** 每次上传同一张图片都重新调用 Qwen-VL API，消耗 token 和时间。
**建议：**
- 图片 hash（MD5/SHA256）+ question 作为缓存 key
- 本地 SQLite 或 Redis 缓存分析结果
- 缓存有效期设为 7 天

### 1.2 图片未压缩
**现状：** 原图直接 base64 编码上传，大图片传输慢、token 消耗大。
**建议：**
- 上传前用 Pillow 压缩（限制最大边 2048px）
- 转为 JPEG 统一格式（减小体积）
- 提供缩略图预览

### 1.3 无批量图片处理
**现状：** 只支持单张图片上传分析。
**建议：**
- 支持多图同时上传
- 批量分析 + 结果汇总
- 图片对比分析（如两张财务报表对比）

### 1.4 图片与文档关联弱
**现状：** `image-chat` 接口将图片分析结果拼接到 query 文本中，作为 RAG 上下文。
**问题：** 图片分析结果可能很长，稀释了检索到的文档相关内容。
**建议：**
- 图片分析结果单独作为 context 块，与 RAG context 分离
- 在 prompt 中明确标注「图片信息」和「文档信息」
- 允许用户选择是否结合文档

### 1.5 图片存储无清理机制
**现状：** 上传的图片永久保存在 `data/images/`，无过期清理。
**建议：**
- 定期清理（如 7 天前的图片）
- 提供图片管理接口（列表/删除）
- 设置存储上限

## 二、安全优化 🔒

### 2.1 API Key 泄露（严重！）
**现状：** `.env` 文件中明文存储了 DeepSeek 和 Qwen-VL 两个 API Key。
**问题：** 这些 key 会被提交到版本控制。
**建议：**
- 立即轮换已泄露的 key
- `.gitignore` 确保 `.env` 不提交
- 使用密钥管理服务

### 2.2 图片上传安全
**现状：** 仅校验扩展名，未检查文件内容。
**建议：**
- 校验图片 magic bytes（JPEG: FF D8, PNG: 89 50 4E 47）
- 用 Pillow 验证图片可解析性
- 限制文件名字符（防止路径穿越）
- 文件名消毒后保存

### 2.3 图片内容安全
**现状：** 未对图片内容做任何过滤。
**建议：**
- 接入内容安全审核（阿里云内容安全 API）
- 过滤违规图片（色情、暴力、政治敏感）
- 记录上传日志用于审计

### 2.4 CORS 全开放
**现状：** `allow_origins=["*"]`
**建议：** 生产环境限制具体域名

## 三、性能优化 ⚡

### 3.1 Qwen-VL 调用优化
**现状：** 同步调用，timeout 60s，无重试。
**建议：**
- 添加重试机制（指数退避，最多 3 次）
- 超时时间可配置
- 支持流式输出（体感更快）
- 并发限制（避免超 quota）

### 3.2 图片 base64 体积
**现状：** 大图片 base64 后体积膨胀 33%，传输慢。
**建议：**
- 前端压缩后再上传
- 后端收到后先压缩再编码
- 考虑使用 OSS 存储图片，传 URL 给 API

### 3.3 图片分析与 RAG 串行
**现状：** `image-chat` 先调 Qwen-VL，再调 RAG，串行执行。
**建议：**
- 两个调用并行执行（asyncio.gather）
- 总延迟 = max(图片分析, RAG) 而非 两者之和

### 3.4 嵌入模型单例
**现状：** 每次 `EmbeddingManager()` 实例化都加载模型。
**建议：** 全局单例 + 启动预热

### 4.1 图片预览体验
**现状：** 前端有图片预览，但分析结果展示较简单。
**建议：**
- 图片分析结果支持 Markdown 渲染
- 图片+文字混合展示
- 分析结果支持复制/导出

### 4.2 图片拖拽上传
**现状：** 前端有 image button，支持文件选择。
**建议：**
- 支持拖拽上传
- 支持粘贴截图
- 上传进度条

### 4.3 pdf.js 外部 CDN
**现状：** 依赖 `cdnjs.cloudflare.com`，国内可能慢。
**建议：** 本地化 pdf.js

## 五、可维护性优化 📝

### 5.1 日志系统
**现状：** 混用 print，无结构化日志。
**建议：**
- 统一 logging 模块
- 图片分析单独日志（含耗时、token 消耗）
- JSON 格式便于采集

### 5.2 测试覆盖
**现状：** `test_system.py` 仅基础测试。
**建议：**
- 图片处理单元测试（各格式、边界大小、损坏文件）
- API 集成测试（上传 → 分析 → 问答）
- Mock Qwen-VL API 做离线测试

### 5.3 配置管理
**现状：** config.py 硬编码了图片格式和大小限制。
**建议：**
- 全部可配置（环境变量或配置文件）
- 运行时动态调整
