# 🌟 招股说明书智能问答系统（LightRAG 双层检索版） — 项目优点分析

> 从 LightRAG 架构、知识图谱、检索引擎、工程质量、多模态能力五个维度，全面展示本项目的核心亮点。

---

## 一、LightRAG 双层检索架构优点 🧠（核心亮点）

### 1.1 双层检索融合
系统实现了 LightRAG 架构，在传统向量检索（低层）之上，增加了知识图谱检索（高层），通过 RRF 融合两层结果：

```
Query → 低层: FAISS 向量检索 → 向量结果
      → 高层: 知识图谱检索 → 图谱结果
      → RRF 融合 → 最终结果
```

这种双层架构的优势：
- **低层**擅长精确语义匹配，找到包含相关信息的文本片段
- **高层**擅长理解实体关系，找到通过图谱连接的间接信息
- **RRF 融合**取两者之长，既不遗漏语义相关也不遗漏关系相关的结果

### 1.2 四种检索模式
系统支持四种检索模式，可通过配置或 API 动态切换：

| 模式 | 原理 | 适用场景 |
|---|---|---|
| `vector` | FAISS 向量检索 | 语义检索 |
| `bm25` | BM25 全文检索 + jieba | 精确关键词匹配 |
| `hybrid` | 向量 + BM25 + RRF + Reranker | 综合效果最优 |
| `lightrag` | 向量 + 知识图谱 + RRF | 需要理解实体关系 |

### 1.3 智能查询分析
`GraphRetriever` 在检索前会调用 LLM 分析查询类型：
- **concrete（具体查询）**：询问具体实体、人物、数字 → 在图中精确匹配节点，取 1-2 跳邻居
- **abstract（抽象查询）**：询问趋势、对比、总结 → 匹配相关子图，生成摘要

这种自适应策略比统一检索更精准。

### 1.4 多跳图遍历
对于具体查询，`GraphRetriever` 支持 1-hop 和 2-hop 图遍历：
- **0-hop**：直接返回匹配节点的属性
- **1-hop**：返回匹配节点及其直接邻居的关系
- **2-hop**：返回通过中间节点连接的间接关系

这使得系统能回答"A 公司的供应商的竞争对手是谁"这类需要多跳推理的问题。

## 二、知识图谱构建优点 🕸️

### 2.1 LLM 驱动的实体抽取
`GraphBuilder` 使用 LLM 从文档 chunks 中自动抽取实体和关系。预定义了 8 种实体类型（公司、人物、产品、事件等）和 10 种关系类型（属于、合作、竞争、投资等），覆盖金融文档常见场景。

### 2.2 智能过滤低价值块
在抽取前自动过滤低价值文本块：
- 跳过纯数字/金额表格
- 跳过中文字符占比 < 15% 的表格数据
- 跳过长度 < 30 字符的碎片

减少无效 API 调用，提升图谱质量。

### 2.3 批量并发 + 限流
- 将多个 chunk 合并为一次 LLM 调用（`batch_size=10`）
- 使用 `ThreadPoolExecutor`（max_workers=4）并发处理
- 每提交一批后暂停 1s，避免瞬时并发过高
- 每次调用前等待 0.5s，分散请求

### 2.4 重试机制
LLM 调用失败时自动重试：
- 限流（429）：指数退避 5s → 10s → 20s
- 超时：指数退避 3s → 6s → 12s
- 空响应：指数退避 2s → 4s → 8s
- 最多重试 3 次

### 2.5 多格式 JSON 容错解析
LLM 返回的 JSON 格式不一致时，系统尝试 5 种解析方式：
1. 直接解析
2. 提取 ```json``` 代码块
3. 提取被截断的 ```json 开头（补全括号）
4. 提取第一个 { ... } 块
5. 修复常见格式问题（尾逗号等）

### 2.6 实体合并与去重
相同实体名（忽略大小写）自动合并：更新描述、类型、出现次数。避免图谱中出现重复节点。

### 2.7 双 API Key 分流
图构建使用独立的 API Key（`DEEPSEEK_API_KEY_2`），与问答 API Key 分离。避免构建图谱时占用问答的 API 配额。

## 三、检索引擎优点 🔍

### 3.1 向量检索（低层）
使用 FAISS 做向量检索，支持 GPU 加速。`EmbeddingManager` 负责文本向量化，`FAISSRetriever` 负责索引构建和检索。

### 3.2 知识图谱检索（高层）
`GraphRetriever` 根据查询在图中查找相关实体和关系。支持具体查询（精确匹配 + 多跳遍历）和抽象查询（子图摘要）两种策略。

### 3.3 RRF 融合
使用 Reciprocal Rank Fusion 融合向量检索和图谱检索结果：`score = Σ 1/(k + rank_i)`。不依赖绝对分数，只看排名，公平融合不同检索器的结果。

### 3.4 索引缓存与秒切
`app_core.py` 实现懒加载 + 索引缓存：首次构建索引后保存到磁盘，后续切换检索模式时直接加载，秒级切换。

## 四、多模态能力优点 🎨

### 4.1 五种输入方式
文字输入、语音输入、图片上传、图片+文档联合问答、批量处理。

### 4.2 多轮对话 + 流式输出
前端维护对话历史，SSE 流式输出逐字渲染。

### 4.3 PDF 文档管理
支持多 PDF 上传、删除、激活/停用。

### 4.4 评估页面
新增 `eval.html` 评估页面，支持在线评估检索质量。

## 五、工程质量优点 📝

### 5.1 清晰的模块化架构

| 模块 | 职责 |
|---|---|
| `config.py` | 集中配置（含 LightRAG 参数、双 API Key） |
| `lightrag_retriever.py` | LightRAG 核心（GraphBuilder + GraphRetriever + LightRAGRetriever） |
| `embedding.py` | 向量化 + FAISS 索引 |
| `app_core.py` | 统一初始化（支持 4 种检索模式） |
| `api_server.py` | FastAPI Web 服务 |
| `image_processor.py` | 图片理解 |
| `frontend/` | HTML/CSS/JS 前端 + 评估页面 |

### 5.2 多级降级策略
- LLM API 不可用 → 本地关键词匹配兜底
- FAISS 检索失败 → 本地余弦相似度检索
- 知识图谱不存在 → 降级为纯向量检索
- 混合检索失败 → 降级为纯 BM25

### 5.3 丰富的 API 接口
FastAPI 提供 17+ 个 RESTful 接口，自动生成 OpenAPI 文档。

### 5.4 配置集中化
所有可调参数集中在 `config.py`，包括 LightRAG 的实体类型、关系类型、跳数、Top-K 等。
