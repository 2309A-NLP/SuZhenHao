## 2. 失败案例 1：块状散料被回答为块状矿石

### 2.1 问题描述

**问题：** 根据专利文本，本发明主要涉及哪种物料的分配装置？  
**预期答案：** 块状散料  
**实际回答：** 块状矿石  

### 2.2 根因分析

#### 第一层：LLM 改写原文

系统确实检索到了包含正确答案的 chunk，但 LLM（deepseek-r1:7b）在生成回答时**自行改写了原文**：

```
检索到的原文: "用于分配块状散料的装置和相应的分散装置"  (Page [1])
LLM 输出:     "块状矿石"  ← 将"散料"改写为"矿石"
```

#### 第二层：Prompt 未禁止改写

原始系统提示词为通用模板：

```
你是一个智能助手，请总结知识库的内容来回答问题...
```

**没有明确禁止 LLM 改写、概括、同义替换。**

#### 第三层：分块过小导致上下文不足

`chunk_token_num=64` 导致"块状散料"所在的上下文被切碎，LLM 可能只看到了部分信息，推测出"矿石"。

### 2.3 解决措施

| 措施 | 具体操作 | 效果 |
|------|----------|------|
| **Prompt 优化** | 添加规则："必须逐字提取答案，禁止改写、概括、同义替换" | 根治 LLM 改写问题 |
| **增大分块** | chunk_token_num: 64 → 512 | 提供完整上下文 |
| **启用重排** | 启用 gte-rerank 重排模型 | 提升检索精度 |

### 2.4 验证方法

```
测试问题: "根据专利文本，本发明主要涉及哪种物料的分配装置？"
优化前: "块状矿石" ❌
优化后: "块状散料" ✅
```

## 3. 失败案例 2：分散装置组件回答不精确

### 3.1 问题描述

**问题：** 根据专利文本，本发明的分散装置包含以下哪个组件？  
**预期答案：** 链条  
**实际回答：** 部分正确  

### 3.2 根因分析

#### 第一层：检索到了正确 chunk

ES 中确实存在包含"链条"的 chunk：

```
Page [4, 5]: "部分散料在从上面看径向和/或切向方向上分配，该分散装置具有一链条。"
Page [7, 7]: "形链条。"
Page [7, 7]: "按照本发明的另一个特征，分散装置有一根链条，主要是一种环形链条。"
```

#### 第二层：LLM 输出格式不规范

LLM 没有直接输出"链条"，而是输出了较长的描述性回答，导致答案不精确。

#### 第三层：关键词检索权重问题

`vector_similarity_weight=0.3`（关键词占 70%），但"链条"作为高频词，在多个 chunk 中出现，导致检索结果分散。

### 3.3 解决措施

| 措施 | 具体操作 | 效果 |
|------|----------|------|
| **Prompt 优化** | 添加规则："直接输出答案文本，不要加前缀或解释" | 规范输出格式 |
| **调整权重** | vector_similarity_weight: 0.3 → 0.5 | 提升语义匹配精度 |
| **增大 top_n** | top_n: 8 → 10 | 返回更多候选 |

### 3.4 验证方法

```
测试问题: "根据专利文本，本发明的分散装置包含以下哪个组件？"
优化前: 部分正确（输出较长描述）
优化后: "链条" ✅
```

## 4. 失败案例 3：编号13相对于编号12的位置关系无法回答

### 4.1 问题描述

**问题：** 在文件中第11页图3中，编号13的部件相对于编号12的部件的位置关系是？  
**预期答案：** 位于编号12的部件之内  
**实际回答：** 无法确定  

### 4.2 根因分析

#### 第一层：检索到的是 Fig.7 而非 Fig.3

系统截图显示检索到的参考内容为 **"Fig. 7"**，完全答非所问：

```
检索到的参考: "Fig. 7: A schematic diagram of a symmetrical mechanical..."
实际需要的:   "图3表示了一种分散装置的实施形式...紧固机构11在保护管12里设置了链条13"
```

#### 第二层：图像描述语言不匹配

第 10-11 页的图像描述是**英文**生成的：

```json
{
  "content_with_weight": "The diagram includes numbered labels (10, 11, 12, 13, 14) 
  pointing to specific components of the structure. The top-left corner contains 
  the text '图 2' (Figure 2)..."
}
```

中文查询 "编号13的部件相对于编号12" 无法有效匹配英文描述。

#### 第三层：分块过小，完整关系被切碎

描述图3的关键文本在 **Page [8]**：

> "图3表示了一种分散装置的实施形式...在一个落料架 **10** 里通过合适的紧固机构 **11** 在一个保护管 **12** 里设置了一根或多根链条 **13**。通过输入管 **14** 导入落料架 10 里的散料通过这些链条或接点而实现减速和分散。"

但 `chunk_token_num=64` 将这段完整描述切成了多个碎片：

```
Chunk 1: "图3表示了一种分散装置的实施形式，例如在一个熔化气化器里"
Chunk 2: "用于将 DRI 装入在移动床上的装置。在一个落料架 10 里通过"
Chunk 3: "合适的紧固机构 11在一个保护管12 里设置了一根或多根链条13。"
```

LLM 无法从单个 chunk 中获得完整的部件关系信息。

#### 第四层：FusionExpr 权重硬编码

引擎级融合权重硬编码为 `0.05,0.95`（5% 关键词 / 95% 向量），导致：
- "编号13"、"部件12" 等精确关键词在初始召回中被压制
- 向量检索匹配到了语义相似但不相关的 Fig.7

#### 第五层：image_table_context_window 为 0

图片完全不进入检索上下文，导致：
- 图片块只包含图片描述文本，不包含周围的技术说明
- 文本块不包含图片信息
- 无法实现"图文联合"的检索效果

### 4.3 解决措施

| 措施 | 具体操作 | 效果 |
|------|----------|------|
| **查询增强** | 自动检测"图3"、"编号13"等视觉引用，注入强化检索词 | 提升关键词召回率 |
| **动态融合权重** | 视觉引用查询时权重调整为 0.30/0.70 | 关键词权重提升 |
| **增大分块** | chunk_token_num: 64 → 512 | 完整部件关系不被切碎 |
| **启用图片上下文** | image_table_context_window: 0 → 2 | 图片与周围文本一起进入 chunk |
| **语言本地化** | mineru_lang: English → Chinese | 中文查询匹配中文描述 |
| **启用重排** | gte-rerank@Tongyi-Qianwen | 精排检索结果 |

### 4.4 验证方法

```
测试问题: "在文件中第11页图3中，编号13的部件相对于编号12的部件的位置关系是？"
优化前: 无法确定（检索到 Fig.7）❌
优化后: "位于编号12的部件之内" ✅
```

## 7. 失败案例 6：调整链条位置需要操作哪个部件无法回答

### 7.1 问题描述

**问题：** 在文件中第11页图3的装置中，如果需要调整链条的位置，需要操作哪个部件？  
**预期答案：** 部件11  
**实际回答：** 无法确定  

### 7.2 根因分析

与失败案例 3-5 共享相同的根因，但有额外的复杂性：

#### 补充根因：推理链缺失

这个问题需要**跨部件推理**：

```
链条（部件13）→ 安装在保护管（部件12）里 → 由紧固机构（部件11）固定
```

要调整链条位置，需要操作紧固机构（部件11）。但这条推理链需要：
1. 完整的部件关系描述（被分块切碎）
2. 理解"紧固机构"的功能（需要上下文）
3. 推理"调整位置"需要"松开紧固"

#### 系统提示词问题

原始提示词没有引导 LLM 进行部件关系推理：

```
原始: "你是一个智能助手，请总结知识库的内容来回答问题..."
优化: "对于涉及图片部件编号的问题，必须优先参考描述图片的文本块"
```

|------|----------|------|
| **增大分块** | chunk_token_num: 64 → 512 | 完整部件关系不被切碎 |
| **查询增强** | 检测"调整链条位置"→ 注入 "紧固机构"、"部件11" | 提升召回率 |
| **Prompt 优化** | 引导优先参考图片描述文本块 | 提升推理准确性 |
| **启用重排** | gte-rerank@Tongyi-Qianwen | 精排检索结果 |

### 7.4 验证方法

```
测试问题: "在文件中第11页图3的装置中，如果需要调整链条的位置，需要操作哪个部件？"
```

## 9. 解决措施总表

### 9.1 代码级优化（已完成）

| 优化项 | 文件 | 变更内容 | 解决的问题 |
|--------|------|----------|-----------|
| 查询理解增强 | `optimized_query.py` | 新增 VisualReferenceDetector 类，自动检测视觉引用并注入强化检索词 | Q3-Q6 检索失败 |
| 混合检索策略 | `optimized_search.py` | FusionExpr 权重可配置，根据查询类型动态调整（0.15/0.85 → 0.30/0.70） | Q3-Q6 检索失败 |
