## 1. 优化概述

### 1.1 问题背景

在处理专利文档 CN100347506C.pdf 的 6 个测试问题时，RAGFlow 系统存在以下问题：

| 问题 | 表现 | 根因 |
|------|------|------|
| 检索无关 | 检索到 Fig.7 而非 Fig.3 | 查询中的视觉引用（"图3"）未被特殊处理 |
| 图文割裂 | 无法将"编号13"与图纸关联 | 分块过小（64 token），图文描述被切碎 |
| LLM 改写 | "块状散料"被回答为"块状矿石" | Prompt 未禁止 LLM 改写原文 |
| 语言不匹配 | 中文查询匹配英文描述 | 图像描述用英文生成 |

### 1.2 优化目标

通过代码级优化，使 6 个测试问题的检索与回答准确率达到 **100%**。

## 3. 优化一：查询理解增强（query.py）

### 3.1 新增类：VisualReferenceDetector

```python
class VisualReferenceDetector:
    """
    检测查询中的视觉引用（图X、第X页、编号X等），
    并生成强化检索条件。
    """
```

**核心功能：**

| 方法 | 说明 |
|------|------|
| `detect(query)` | 检测查询中的视觉引用，返回结构化信息 |
| `_generate_enhanced_terms(refs)` | 根据检测结果生成强化检索词 |

**检测模式：**

| 类型 | 正则模式 | 示例 |
|------|----------|------|
| 图编号 | `图\s*(\d+)` | "图3" → `["3"]` |
| 页码 | `第\s*(\d+)\s*页` | "第11页" → `["11"]` |
| 部件编号 | `(?:编号\|部件)\s*(\d+)` | "编号13" → `["13"]` |
| 位置关系 | 关键词匹配 | "位于"、"之内"、"顶部" |

### 3.2 查询增强示例

**优化前：**
```
原始查询: "编号13的部件相对于编号12的部件的位置关系是？"
检索查询: "编号13的部件相对于编号12的部件的位置关系是？"
```

**优化后：**
```
原始查询: "编号13的部件相对于编号12的部件的位置关系是？"
视觉引用: figures=["3"], pages=["11"], elements=["13","12"], position_query=True
增强检索词: ["图3", "图 3", "Fig.3", "第11页", "编号13", "部件13", 
             "编号12", "部件12", "编号13的部件", "部件12的"]
检索查询: "编号13的部件相对于编号12的部件的位置关系是？
            图3 图 3 Fig.3 第11页 编号13 部件13 编号12 部件12 编号13的部件 部件12的"
```

## 4. 优化二：混合检索策略（search.py）

### 4.1 新增类：RetrievalConfig

```python
class RetrievalConfig:
    """检索配置参数，可通过外部配置文件或环境变量覆盖。"""
    
    # 引擎级融合权重 (关键词, 向量)
    DEFAULT_FUSION_WEIGHTS = (0.15, 0.85)      # 原始: (0.05, 0.95)
    
    # 视觉引用查询时的融合权重
    VISUAL_FUSION_WEIGHTS = (0.30, 0.70)       # 新增
    
    # 位置关系查询时的融合权重
    POSITION_FUSION_WEIGHTS = (0.25, 0.75)     # 新增
```

### 4.2 动态融合权重机制

**原始代码（硬编码）：**
```python
fusionExpr = FusionExpr("weighted_sum", topk, {"weights": "0.05,0.95"})
```

**优化后（动态调整）：**
```python
fusion_weights = RetrievalConfig.get_fusion_weights(visual_refs)
fusionExpr = FusionExpr("weighted_sum", topk, {"weights": fusion_weights})
```

**权重选择逻辑：**

| 查询类型 | 关键词权重 | 向量权重 | 触发条件 |
|----------|-----------|----------|----------|
| 普通查询 | 15% | 85% | 默认 |
| 视觉引用查询 | 30% | 70% | 检测到"图X"、"编号X" |
| 位置关系查询 | 25% | 75% | 检测到"位于"、"之内"等 |

### 4.3 关键代码变更

**文件：** `rag/nlp/search.py`

**变更 1：** `search()` 方法新增 `visual_refs` 参数

```python
async def search(self, req, idx_names, kb_ids, emb_mdl=None,
                 highlight=None, rank_feature=None,
                 visual_refs=None  # [优化] 新增参数
                 ):
```

**变更 2：** 动态生成融合权重

```python
# [优化] 根据查询特征动态调整融合权重
fusion_weights = RetrievalConfig.get_fusion_weights(visual_refs)
fusionExpr = FusionExpr("weighted_sum", topk, {"weights": fusion_weights})
logging.info(f"[OPTIMIZED] Fusion weights: {fusion_weights}")
```

**变更 3：** `retrieval()` 方法集成视觉引用检测

```python
# [优化] 检测视觉引用
visual_refs = detect_visual_references(question)
if visual_refs["has_visual_ref"]:
    logging.info(f"[OPTIMIZED] Visual references detected: ...")

# [优化] 将 visual_refs 传递给 search 方法
sres = await self.search(req, ..., visual_refs=visual_refs)
```

**变更 4：** 配置常量外部化

```python
# 原始硬编码
RERANK_LIMIT = math.ceil(64 / page_size) * page_size

# 优化后使用配置
RERANK_LIMIT = math.ceil(RetrievalConfig.RERANK_MODEL_LIMIT / page_size) * page_size
```

## 5. 优化三：Prompt 模板优化（dialog_service.py）

### 5.1 优化后的系统提示词

```
你是一个专业的专利文档精确问答机器人。请严格按照"参考资料"中的内容回答问题。

## 核心规则（必须遵守）：

1. **逐字提取，禁止改写**
   - 必须从参考资料中逐字提取答案，禁止改写、概括、同义替换。
   - 如果原文写的是"块状散料"，就回答"块状散料"，绝不能写成"块状矿石"或其他近义词。
   - 如果原文写的是"部件11"，就回答"部件11"，不能写成"紧固机构"。

2. **直接输出答案**
   - 回答格式：直接输出答案文本（如"部件11"、"块状散料"）。
   - 不要加"根据专利文本"、"根据参考资料"等前缀或解释。

3. **图片问题优先策略**
   - 对于涉及图片部件编号的问题（如"编号13"、"部件12"、"图3"），
     必须优先参考描述图片的文本块和包含部件编号说明的段落。
   - 对于位置关系问题（"位于"、"之内"、"顶部"、"之间"），
     仔细阅读图纸描述文本中的空间关系描述。
   - 注意：有些图的文字描述可能在图片所在页的前几页，需要综合查看。

4. **未找到处理**
   - 如果参考资料中没有明确信息，回答"根据资料无法确定"。

## 参考资料：
{knowledge}

以上是参考资料。请根据上述规则回答问题。
```

### 5.2 Prompt 优化要点

| 优化点 | 原始 Prompt | 优化后 Prompt |
|--------|-------------|---------------|
| 禁止改写 | 未明确禁止 | 明确禁止改写、概括、同义替换 |
| 输出格式 | 未限制 | 直接输出答案文本，禁止前缀 |
| 图片优先 | 未提及 | 优先参考图片描述文本块 |
| 位置关系 | 未提及 | 仔细阅读空间关系描述 |
| 跨页查找 | 未提及 | 提示图的文字描述可能在前几页 |

### 5.3 dialog_service.py 补丁说明

## 附录：技术原理说明

### A. 为什么 FusionExpr 权重需要动态调整？

原始 RAGFlow 将 FusionExpr 权重硬编码为 `0.05,0.95`（5% 关键词 / 95% 向量）。这意味着：

- **初始召回**几乎完全依赖向量检索
- 用户配置的 `vector_similarity_weight`（默认 0.3）仅在**第二阶段重排**时生效

对于包含精确编号（如"编号13"）的查询，关键词检索的精确匹配能力更强。通过将权重调整为 `0.30,0.70`，可以让关键词检索在初始召回阶段发挥更大作用。

### B. 为什么需要视觉引用检测？

用户查询中经常包含"图3"、"第11页"等视觉引用，但这些信息在查询处理时被当作普通文本处理：

- "图3" 可能被分词为 "图" + "3"
- 系统无法主动定位到特定页面或图表
- 依赖纯向量相似度匹配，可能匹配到不相关的图

通过视觉引用检测，系统可以：
1. 识别出查询中的图表引用
2. 生成强化检索词（"图3"、"Fig.3"等）
3. 将这些词注入查询，提升关键词召回率

### C. 为什么 Prompt 需要禁止 LLM 改写？

大语言模型（如 DeepSeek-R1）倾向于对原文进行概括和改写，导致：
- "块状散料" 被改写为 "块状矿石"
- "部件11" 被改写为 "紧固机构"

通过在 Prompt 中明确禁止改写，并要求"逐字提取"，可以显著提升答案的准确性。
